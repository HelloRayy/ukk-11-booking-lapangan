Kamus File Codebase & Prinsip Tanggung Jawab Tunggal

Setiap berkas memiliki 1 tugas spesifik (Single Responsibility Principle). Pahami peran tiap berkas agar kamu tahu persis kemana harus menuju saat penguji meminta modifikasi.

1. Lapisan Basis Data & Koneksi (Database Layer)
src/types/database.ts TypeScript Model

Peran Utama: Menetapkan kontrak tipe data untuk tabel lapangan dan bookings. Menjamin TypeScript memvalidasi kolom sebelum query dikirim.

// Kolom Kunci:
• lapangan.status: 'Aktif' | 'Tutup' (Fitur Disable)
• bookings.jam_slots: string[] (Array jam text)
• bookings.no_hp: string (Bukan number agar 0 tidak hilang)
Tanya Penguji: "Mengapa dibuat file types terpisah?" → Jawab: "Agar tipe data dipakai bersama secara konsisten antara backend api dan frontend komponen tanpa duplikasi kode."
src/lib/supabase.ts Client Init

Peran Utama: Menginisialisasi koneksi klien tunggal (singleton) ke server Supabase PostgreSQL menggunakan URL dan Anon Key dari berkas .env.

// Kode Kunci:
const supabaseUrl = import.meta.env.VITE_SUPABASE_URL
const supabaseAnonKey = import.meta.env.VITE_SUPABASE_ANON_KEY
export const supabase = createClient(supabaseUrl, supabaseAnonKey)
Tanya Penguji: "Mengapa URL database tidak ditulis langsung di dalam kodingan?" → Jawab: "Untuk keamanan dan fleksibilitas (*Separation of Secrets*), sehingga kredensial disimpan aman di variabel lingkungan .env."
2. Lapisan Controller & Logika Bisnis (Backend Service Layer)
src/lib/api.ts API Controller

Peran Utama: Jantung backend aplikasi. Seluruh fungsi CRUD tabel master lapangan, pengecekan slot jam bentrok, pembuatan booking baru, hingga update status pelunasan berada di berkas ini.

// 4 Fungsi Master & 3 Fungsi Transaksi:
• getLapangan, createLapangan, updateLapangan, deleteLapangan
• getBookedSlots(courtId, date): Cek jam bentrok
• createBooking(data) & updateStatusBooking(id, status, sisa)
Tanya Penguji: "Mana kode SQL INSERT dan UPDATE kamu?" → Jawab: "Query dijalankan lewat Supabase Query Builder di api.ts: supabase.from('lapangan').insert(...) dan .update(...)."
src/utils/costCalculation.ts Aritmatika Helper

Peran Utama: Menjalankan syarat penilaian Poin 4 Kisi-Kisi UKK (Kalkulasi Aritmatika Otomatis). Menghitung total biaya sewa dari durasi x tarif, serta membagi tagihan DP 50% dan sisa bayar.

// Rumus Bisnis:
const totalCost = durationHours * ratePerHour;
const downPayment = totalCost * 0.5; // DP 50%
const remainingCost = totalCost - downPayment;
Tanya Penguji: "Coba ubah aturan DP jadi 30%!" → Jawab: "Buka costCalculation.ts lalu ubah angka pengali 0.5 menjadi 0.3."
3. Lapisan Antarmuka Publik & Kasir (UI & Dashboard)
src/components/cashier/dashboard-01/CourtsManagementView.tsx Master CRUD

Peran Utama: Panel khusus admin kasir untuk mengelola master lapangan: Menambah lapangan baru (Create), mengedit tarif (Update), menghapus (Delete), dan saklar toggle status Aktif <-> Tutup.

// Saklar Toggle:
const statusBaru = court.status === 'Aktif' ? 'Tutup' : 'Aktif'
await updateLapangan(court.id, { status: statusBaru })
Tanya Penguji: "Di mana fitur CRUD kamu dibuktikan?" → Jawab: "Di tab Kelola Lapangan kasir: tambah data dari form modal, edit tarif, hapus data, dan ubah status operasional."
src/components/cashier/dashboard-01/BookingsTable.tsx Tabel Transaksi

Peran Utama: Menampilkan tabel riwayat transaksi, kotak live-search nama penyewa, filter status (Semua / Belum Lunas / Lunas), dan tombol aksi "Lunasi" untuk pembayaran sisa tagihan DP.

// Aksi Pelunasan Kasir:
const handleLunasi = async (id) => {
await updateStatusBooking(id, 'Lunas', 0)
loadDataKasir() // refresh tabel otomatis
}
Tanya Penguji: "Apa yang berubah di database saat tombol Lunasi ditekan?" → Jawab: "Kolom status diubah menjadi 'Lunas' dan kolom sisa_bayar diperbarui menjadi Rp 0."
